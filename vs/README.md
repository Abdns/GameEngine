# Visual Studio

Открывай `vs\Open.cmd`: он синхронизирует файлы проекта и фильтры с папками на
диске, затем открывает `Engine.sln`. Синхронизация также запускается при сборке.
Для ручного обновления выполни `vs\Sync-Projects.ps1` через PowerShell.
Если VS предложит перезагрузить изменённые проекты, выбери перезагрузку.

Создавай и перемещай файлы в реальных папках. Фильтры создаются по их путям:
перетаскивание внутри фильтров VS само по себе не перемещает файл на диске.
При добавлении файла через VS проверяй поле «Расположение».

IntelliSense использует обычные C++ проекты. Только `Game.cpp`, `Program.cpp`
и `AssetBuilder.cpp` отмечены как отдельные единицы компиляции; включаемые `.cpp`
получают контекст из них. Сборкой по-прежнему управляет `build.bat`.

**F5** запускает Engine под отладчиком. **Ctrl+Alt+1 / Ctrl+Alt+4** — внешние
команды сборки, которые могут запускать игру без подключения отладчика.
Для разбора падения используй F5. **Ctrl+S** пересобирает Game DLL, если включён
`HOT_RELOAD` и установлено расширение VSERunOnSave.

Сохранение `.hlsl` или заголовка в `Graphics\Vulkan\shaders` запускает
`build.bat on-save-shaders`. Компилятор сначала собирает весь набор во временную
папку, затем публикует `.spv` и метку `shaders.ready`. При ошибке компиляции
продолжает работать предыдущий набор; ошибки видны в выводе VSERunOnSave.

В сборке с `ENGINE_INTERNAL=1` рендер проверяет метку раз в 250 мс и заменяет
шейдеры между кадрами, дождавшись завершения GPU. В выводе движка появляется
`[shaders] Reloaded shader set.`. Ручная сборка через Ctrl+Alt+2 также вызывает
перезагрузку. Состояние игры при этом сохраняется.

После первого добавления механизма перезагрузки нужно перезапустить движок:
этот код находится в `Engine.exe`. Изменения общего интерфейса C++/HLSL
(структур данных, bindings, push constants) требуют согласованной пересборки
обеих сторон и перезапуска.
